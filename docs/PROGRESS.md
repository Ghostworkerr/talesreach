**How the world is built now (from 2.1):**
- Maps are generated by scripts: `npm run maps` runs `tools/maps/build-inn.mjs` (inn interior,
  `assets/maps/inn.tmj`), `tools/maps/build-region.mjs` (the 128×128 Crossroads region,
  `assets/maps/crossroads.tmj`) and `tools/maps/build-chunks.mjs` (cuts every map into
  `assets/maps/<name>/meta.json` + 32×32-tile chunk files for the client). Shared helpers in
  `tools/maps/lib.mjs`. A test fails if the chunk files are out of date — rerun `npm run maps`.
- Server (`server/src/rooms/WorldRoom.ts`): one world room serves all maps (`WORLD_MAPS` in
  `shared/src/constants.ts`). `PlayerState.map` says where each player is. New characters arrive in
  the inn (`START_MAP`). Door zones (Tiled objects of type "door" with props `to` + `spot`, read by
  `doorAt` in `shared/src/map.ts`) are checked by the server each tick; it moves the player and sends
  `travel` {map,x,y,ack}. Interest management: `@view()` on players/npcs + a `StateView` per client,
  refreshed 4×/s (`VIEW_RANGE` 420 px in, `VIEW_RANGE_LEAVE` 500 px out, same map only).
  Local chat, inn actions and NPC talk all check the map too. NPCs live in the inn map.
- Client: `client/src/worldMap.ts` (`StreamedMap`) loads a map's meta, then chunks around the camera
  (and unloads far ones; lights come and go with chunks). `WorldScene.travel` fades out, swaps map,
  `Predictor.teleport`s, fades in. Opening cutscene now starts outside at the crossroads, pans to the
  inn's door, fades inside, then the creator.
- Known small polish items: market stall art reads like little flags; the region has big empty
  grass areas (add more detail in a later polish pass); dirt inner-corner tiles look OK but were
  never checked closely.

## Known issue: "The world is waking up…" takes a long time
The game server is on Render's **free** plan, which puts it to sleep after ~15 minutes with no
players. The first visit after that waits while it starts (usually 30–60 s, sometimes up to ~2 min
on a busy day; the game keeps retrying for 2.5 min and shows the seconds). Checked 2026-11-23: the
server was healthy and woke in ~11 s. The homepage now starts waking the server as soon as it opens,
so by the time you press Play it is usually ready. Ways to remove the wait completely (owner's choice):
- Render paid "Starter" plan (~$7/month) never sleeps; or
- a free uptime pinger (e.g. UptimeRobot) calling https://talesreach-server.onrender.com/health every
  10 minutes keeps it awake (uses free-plan hours; fine for one service).
Also: without `DATABASE_URL`, every server restart forgets accounts — devices quietly re-register,
but characters are lost. Setting up the Neon database (below) fixes that.
